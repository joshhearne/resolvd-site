`v0.10.0` is the biggest release so far, and it's really three releases stacked. The headline is that Resolvd can now read **[Trove KB](https://trove-kb.com/)**, our documentation platform, as a knowledge base — beside the built-in KB, or instead of it. The built-in per-project KB stays; nothing changes on upgrade unless you turn the integration on. Underneath that: **custom forms** with computed fields (the HR-onboarding "give me the username and the initial password" problem), **recurring ticket schedules**, **personal tasks**, a **vendor-reply status engine**, and a stack of inbound, SLA, and dashboard fixes that each came out of a real ticket.

## Trove KB integration

Resolvd's built-in KB — per-project BlockNote articles, version history, runbook checklists — is enough for a team's fixes. When your docs outgrow it, or they already live in [Trove KB](https://trove-kb.com/) with the vendor manuals and client docs, point Resolvd at that instance. It reads Trove KB over its REST API with one key and decides on its own side who sees what.

Three ways to run it: **local only** (the default), **side by side** (local project cards and Trove KB collections under `/kb`, the local panel and the Trove KB block on every ticket), or **Trove KB only** after an optional one-click migration.

When Trove KB is connected, **Trove KB owns its content** (articles, runbook definitions, categories, public vs. internal) and **Resolvd owns the ticket state** (links, runbook step progress, resolution summaries, briefs). The built-in KB keeps working exactly as before alongside it.

![The /kb landing page: built-in project KBs, with Trove KB collections listed above them once the integration is connected](/blog/v0-10-0/kb-collections.png)

What you get in Resolvd:

- **Browsing.** `/kb` lists every readable collection as cards. A collection opens to a category / subcategory rail with counts, a type filter (Articles / Runbooks, plus source format once Trove KB reports it), cards-or-list remembered per browser, sort by title or modified, cursor paging, and a search scoped to the collection. Articles render as Markdown at `/kb/article/:id` with breadcrumbs back into the tree.
- **Favorites and helpful votes** act for the signed-in person's email, so a star in Resolvd is the same row they have on the public Trove KB site. `/kb` lists *My favorites*.
- **Ticket block.** Links (title + collection snapshotted so the ticket reads right when Trove KB is down), title-based suggestions that search the project's mapped collection first, and search-to-link.
- **Resolution draft.** An extractive digest always — per article the matched passage, link, and runbook steps. An AI summary on top when the caller may use AI Assist; the response says so when they can't.
- **Knowledge briefs.** *Scope with knowledge* on the comment composer assembles what the user reported, what the team said, the tech's draft and corrections, the project context, and matched articles into a reviewable form. Build without AI by default, or rewrite with AI under rules that keep internal articles out of the reply. Every run is stored in `ticket_assist_briefs` with inputs and output.
- **Noise filter.** Comments that say nothing about the problem (SLA notices, project moves, merges, OOO auto-replies) are kept out of briefs by admin-managed rules in `trove_kb_noise_rules` — regex, literal, or a specific account — with a test box. Built-ins are seeded as rows you can disable or edit.
- **Runbooks from Trove KB.** `kind: runbook` articles carry a `steps[]` array with stable ids. `ticket_runbook_runs` keys step state by that id; a step's `canned` field becomes the 📋 pill. Recurring ticket schedules can name a runbook and start a run on every fire.
- **Promote-to-KB** upserts the resolved ticket into the project's collection as an internal-only draft under `resolvd:ticket:<id>`.

**Visibility** is decided in Resolvd. Project handlers see internal + public; everyone else sees public collections only, and only articles Trove KB confirms public. Resolvd sends `audience=public` on non-handler reads when Trove KB's OpenAPI declares it, and falls back to a per-hit `public_url` check when it doesn't. Strict mode (default on) means a non-handler sees nothing from a collection until Trove KB says it's public. Only Resolvd Admins get links into the Trove KB staff UI.

**Kept in step.** `POST /api/trove-kb/webhook` receives `kb.article.upserted` / `kb.article.archived` with an `X-Trove-Signature` HMAC-SHA256 check (constant time, raw body, 204 / 401 / 400 / 503). The 60 s result cache drops on delivery. Collections sync hourly and on demand — new public ones auto-map Public when the toggle is on, and a Hidden choice is never undone. Titles on links and runs refresh nightly. A *Check for changes now* button polls on demand.

**Migration (optional).** If you'd rather run Trove KB only, Admin → Trove KB → *Replace local KB* shows the plan first: each local article's twin in Trove KB (by `external_id`), links, runs, step coverage. Apply copies `ticket_kb_links` → `ticket_trove_kb_links`, re-keys runbook progress from BlockNote block ids to Trove KB step ids, archives the local articles, and sets `local_kb_enabled = false`. Local tables are kept one release for rollback, and skipping the migration is a perfectly good end state. `scripts/export-kb-to-trove-kb.js` turns BlockNote JSON into Markdown + frontmatter in Trove KB's import layout.

Setup is Admin → Integrations → **Trove KB**: base URL, public URL, API key (encrypted under `RESOLVD_MASTER_KEY`), test connection, Internal / Public / Hidden per collection, webhook secret. Project ↔ collection lives in Admin → AI Assist → Project contexts. The full page is at [resolvd.dev/kb](/kb/).

## Custom forms + computed fields

Category → form → field, scoped per project. A field is required only on the forms that opt in, so a mandatory HR field never bleeds into a DevOps ticket.

- **Field defs are project-local** with tag-prefixed slugs (`hr-username`) and a collision guard. Soft-archive, never hard delete. `sensitive` and `agent_only` flags.
- **Agent-only fields** are hidden from the submitter's new-ticket form and filled by handlers on the ticket's Custom Fields card — per-field or save-all via `PATCH /api/tickets/:id/custom-fields`.
- **Multiselect** field type: JSON-array values, checkbox groups on the form and the card, options-validated, joined display.
- **`{field.<slug>}`** resolves in canned responses and vendor email templates (hyphen-tolerant; sensitive values revealed for the composing agent; HTML-escaped in HTML templates). Tag pickers insert at the caret and expose a project-scoped *Custom fields* chip group.
- **Deep-linkable new-ticket URLs**: `/tickets/new/<project-prefix>/<category-slug>/<form-slug>?<field-slug>=<value>`, resolving left-to-right; selects pre-fill by 1-based option number. Admin → Forms has a shareable-link builder.
- **Per-category default form**, auto-selected on new ticket.
- **Computed fields.** A safe formula over the ticket context — form inputs via `{field.<slug>}` plus `{ticket.*}` / `{submitter.*}` / `{assignee.*}` / `{actor.*}`. Tokenizer + recursive-descent parser + tree-walk evaluator; no `eval`, no globals. Functions: `slice left right upper lower cap pad trim len digits replace match concat default if datepart`, `~` for concat, arithmetic and comparisons. Evaluated on ticket create and on demand via `POST /api/tickets/:id/recompute-fields`. A `/formula-preview` dry-run endpoint and an inline demo preview in the editor.

```
# HR onboarding: derive the AD / M365 UPN from form inputs
lower(left({field.hr-first-name}, 1) ~ {field.hr-last-name}) ~ "@" ~ {field.hr-domain}
```

![Admin → Forms with a computed field editor](/blog/v0-10-0/admin-forms-computed.png)

Admin nav: *Forms / Fields* (first in the group) and *Assets / Fields*. Consumables are now a custom-field entity too (defs only; the value UI on the consumable page is next).

## Recurring ticket schedules

`ticket_schedules`: preset (daily / weekly / monthly by day-of-month / monthly nth weekday / yearly) compiled to cron, with a raw cron escape hatch. Timezone-aware. End condition: indefinite, after N fires, or until a date. Template fields: project, title, description, impact, urgency, optional assignee, optional requestor, contacts, followers (auto-added on every fire), and a runbook that starts a run on every fire.

Each fire materializes a real first-class ticket — ref, encrypted patch, contacts, deduped followers, SLA policy, blind index. `ticket_schedule_runs` is the ledger (ok / error + message). The 60 s tick advances `next_fire_at` on failure too, so a permanently broken template never busy-loops. Description `@mentions` are deliberately not dispatched on create — repeated fires would spam.

Bulk Entra import rides in the same commit: pick users from the directory and add them in one shot.

![Admin → Schedules with recurring ticket templates](/blog/v0-10-0/admin-schedules.png)

## Personal tasks

`tasks` + `task_completions`. Owner-scoped, no fanout, no SLA. Encrypted title + body. One-off `due_at` or recurring (preset or cron) sharing the same iterator math as schedules. Optional `ticket_id` so a task created from a ticket page carries the source ref (`ON DELETE SET NULL` keeps the nudge alive if the ticket is hard-deleted).

`/tasks` page with pending / completed / cancelled chips, edit modal, reschedule and skip. Dashboard gets a **My tasks** card (Overdue / Due today / Tomorrow) with an inline complete checkbox. A global **New** menu in the header creates a ticket or a task from anywhere.

## Vendor-reply auto-status engine

Inbound vendor replies are classified — `completed` (complete / resolved / finished), `acknowledged` (ack / confirm / acknowledge), or neither — and move the **external** status without yanking the ticket off the team's queue:

- ack → external In Progress, internal unchanged (still theirs)
- completed → external Resolved + internal Pending Review (flagged)

Gated to externally-engaged tickets (internal External Escalation or an external ref attached). The classifier runs *before* the awaiting-input resume logic so an ack doesn't pull an escalated ticket back to In Progress. Reopening a ticket with an external ref bumps the external side back to In Progress; purely internal reopens leave it alone.

## Dashboard: buckets, SLA fixes, drill-downs

Every dashboard number now maps to a ticket list you can click.

![Dashboard with status buckets, SLA cards, and the My tasks card](/blog/v0-10-0/dashboard-buckets.png)

- **Status buckets.** Many internal statuses → one card (was 1:1 and silently dropped Acknowledged / On Hold / External Escalation / Resolved). In Progress ← +Acknowledged; Awaiting Input ← +On Hold +External Escalation; Flagged for Review ← Reopened; Closed ← +Resolved. Ticket-list presets match the same sets.
- **SLA metrics.** *Open with SLA clock* was counting closed legacy tickets that never stamped a first response. Live guard on all live counts. Distinct open vs. breached clocks so a ticket owing both response and resolve isn't double-counted. Priority distribution excludes Resolved.
- **Drill-downs.** `?active=1` and `?sla=open|breached|mtd_response|mtd_resolve` on the ticket list; priority bars, MTD breach cards, and the SLA cards all link to their exact set.
- **Per-vendor wait breakdown.** The Vendor wait stat gets a hover popover listing each vendor's slice, with a pulsing dot on rows that have a ticket currently paused on them. Attribution goes to the first vendor contact on the ticket.

## Alerts: acknowledged state

Alerts gain `acknowledged` alongside firing / recovered / suppressed. When an alert-driven ticket leaves Open (single or bulk), the linked firing alert flips to acknowledged and drops off the default Problems board — ticket statuses aren't rewritten. A refire of the same `event_id` flips it back. Alerts page state dropdown → chip toggles; bulk Acknowledge / Unacknowledge. Alert sources get an integration-wide **promotion delay**, so a flapping alert that recovers inside the window never opens a ticket. Dedup note on new pair creation lists recent tickets from the same submitter, flagging rows where the same consumable was already dispatched.

## Consumables: allocation + restock

Printing a consumable delivery label from a ticket now **allocates stock**: first dispatch locks the row, decrements by 1, logs a movement with host + date, and refuses with `409` at zero — posting a system comment on the ticket and an admin notification with the right restock CTA (purchase URL for self-serve, vendor contact copy for metered). Reprints skip the decrement and log a zero-delta movement so the ledger shows extra labels. Crossing the low-stock line fires a 🟡 system comment.

New columns: `purchase_url`, `vendor_part_no`, `is_metered`, `reorder_qty`, and a `location` field with a standalone shelf label for bin marking. Two global canned responses seeded under `consumable_restock`. Canned rendering resolves `{consumable.*}`, `{vendor.*}`, `{ticket.host}`, `{user.display_name}`.

Alert ingest matches a `part.number` tag against consumables at promotion time and posts a system comment for unmatched / out-of-stock / low cases instead of waiting for someone to try printing. The label picker no longer silently defaults to the first consumable; a ↻ Rescan button re-runs the match against the alert tag and the latest title + description.

## Inbound email

- **`[REF]` reply routing.** A message carrying a `[PREFIX-N]` reference is appended to that ticket (vendor contacts and internal participants alike), with an admin-configurable staleness threshold before falling through to auto-create. Out-of-office auto-replies land as muted comments with no status change or fanout. Settings under Admin → Statuses.
- **M365 external-sender banners** are stripped before reply extraction. The "You don't often get email from…" line sat above the reply and matched the contact-email boundary at position 0, so the comment landed as *(no body)*. Boundary tightened to short, non-sentence lines.
- **Our own notifications looping back** (SLA mail, "Ticket closed" to a help-desk mailbox that follows the ticket) are recognized as system notices: muted, no author, no fanout, nothing reopens.
- **Self-healing Graph subscriptions.** A lapsed subscription used to be PATCHed hourly forever on a 404. Now it's recreated, and the inbox is swept from the last known-good timestamp (capped at 14 days). When recreate fails too, the scheduler polls the inbox anyway with a watermark, and System health shows amber *Degraded (polling)*. Auto-loop detection split into hard (our own `X-Resolvd-No-Reply`) and soft (`Auto-Submitted` / `Precedence: bulk`); drops persist as discarded rows.
- **Show original email.** The stripped source (signature, quoted history, banners) is no longer lost. Handlers get a lazy-fetched *Show original email* toggle under the description and inbound comments. Reply-to-self quotes no longer get mis-detected as forwards.
- **Code survives the round trip.** `<pre>` / `<code>` in Outlook and Gmail HTML are fenced before the tag stripper runs, so pasted PowerShell renders as a code block on the ticket.
- Inbound and alert-created tickets now **stamp SLA and run assignment policies** inside the create transaction, instead of a wall-clock backfill that ignored business hours.

## SLA + escalations

- **Escalation delays walk through business hours.** A 30-minute step on a breach at 4:55 PM no longer fires at 5:25 PM outside the window when the policy pins business hours.
- **Handler self-reply ticks the first-response clock.** Alert-promoted tickets often end up with the on-call agent as submitter; their reply is still the real first response.
- **No response breach during the Resolved grace window.** Tickets that resolved before anyone manually replied (transient alerts) kept tripping the breach every minute.
- **Submitters excluded from SLA warning / breach fanout** by default. `auth_settings.sla_notify_submitter_default` flips the global; per-priority chains opt in with a `notify_submitter` action.

## Comments + composer

- **Post & any status.** The "Post & …" menu lists every internal status the ticket can transition to, including custom ones. Falls back to the full list when the transitions graph is empty. A per-status **Post & menu** toggle in Admin → Statuses curates it.
- **Comment signature.** Per-user sign-off with `vendor_only` (default) or `all` scope, live preview, 2000-char cap, appended with a markdown hard break so line breaks survive.
- **Markdown.** Inline backticks were rendering as blocks after the react-markdown v9 upgrade — fixed. Fenced blocks get a language badge and a hover Copy button.
- Composer grows to six rows; the Post & dropdown is portaled with flip-up so it doesn't force a page scroll near the bottom.

## Sessions, SSO, deep links

- **30-day rolling session cookie.** Was a fixed 8-hour absolute window that forced a full M365 re-login mid-workday.
- **Return to the deep link after SSO.** `?returnTo=` captured by the route guard, threaded through the OAuth state param, validated on both ends (rejects `//host` and `/\host`). MFA challenge still lands on the dashboard — known gap.
- **Mention emails link straight to the response** via `?comment=<id>` and the existing scroll-and-flash.

## Admin + users

- **Admin search.** A search box above the admin nav filters by label, group, or per-page keyword aliases (`OOO`, `blocklist`, `oauth`, `recurring`).
- **Users.** Auto-provision resolves via Graph then Google Admin Directory; a Graph hit binds `entra_oid` and links location via company membership. `auth_settings.allow_email_unknown_users` gates local fallback so the ingestion mailbox isn't a spam vector. Bulk select bar (refresh from directory, enable, disable); per-row kebab with viewport-aware flip.
- **New-ticket fanout.** `new_ticket` notification on every create path (REST, inbound, alert promotion) to active Admins / Managers, in-app on and email off by default.
- **Inline assignee picker** on the ticket header: assign to me, change, clear. Pool matches the assignment-policy pool.
- **Print a consumable delivery label from the ticket** (SR flow).

## Removed

- **Inky phish-report handling.** No longer in use. The generic pieces stay: dedup-omit rules, banner-strip presets, link-preserving HTML strip.

## Upgrade notes

- **Trove KB.** Optional. Nothing changes on upgrade: the built-in KB keeps working with the integration off, on, or beside it. *Replace local KB* is a separate, optional step; after it `/kb` reads Trove KB only and `kb_articles` and friends stay for one release. Resolvd needs a Trove KB build with `/api/v1/kb/*` routes; favorites, votes, and `audience` light up automatically when its OpenAPI declares them.
- **Renamed tables** (in place, idempotent): `bothy_settings` → `trove_kb_settings`, `ticket_bothy_links` → `ticket_trove_kb_links`, `ticket_runbook_runs.bothy_article_id` → `trove_kb_article_id`, `projects.bothy_collection_id` → `trove_kb_collection_id`. Only relevant if you ran a pre-release build.
- **New tables:** `ticket_categories`, `ticket_forms`, `ticket_form_fields`, `ticket_schedules`, `ticket_schedule_runs`, `tasks`, `task_completions`, `ticket_assist_briefs`, `trove_kb_noise_rules`, `ticket_trove_kb_links`. New columns on `custom_field_defs`, `custom_field_values`, `tickets.form_id`, `consumables`, `statuses.show_in_post_actions`, `alerts` state CHECK, `auth_settings`, `auto_resolve_settings`, `email_backend_accounts.inbox_last_swept_at`. All `IF NOT EXISTS`, no manual migration.
- **Sessions.** Existing sessions carry over; the 30-day rolling window applies from the next request.
- **`/api/inbound`** accepts 30 MB JSON bodies now (attachments ride inline as base64). Check any reverse proxy limit in front of it.
- **Nav.** New entries: Tasks (everyone), and the global New menu. Admin nav: Forms / Fields, Assets / Fields, Trove KB, Schedules.
